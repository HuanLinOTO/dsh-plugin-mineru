## 迁移步骤

插件代码 **无需任何改动** 即可在 alpha.2 下工作。按顺序执行：

### 1. 升级 dsh 源码 checkout 到 alpha.2（dsh/ 目录写操作，须由人类按 SOP 执行）

`D:/Projects/deepseek-harness/dsh` 当前停在 alpha.1（`git describe` = `dsh-v0.1.2-alpha.1`）。本插件不修改 dsh/，但 profile 的 peer 解析与 typecheck 都经由指向该树的 junction，因此**必须先完成 dsh 侧升级**（`~/.dsh/source/current` 与 dev clone 是同一棵树）：

```powershell
# 由人类执行（本指南不代跑）：pull 到 alpha.2 → pnpm install → pnpm run build
git -C D:/Projects/deepseek-harness/dsh pull --ff-only origin master   # 或 checkout dsh-v0.1.2-alpha.2
pnpm install --prefer-off-line ; pnpm run build   # workdir=dsh，前台长 timeout
```

> 本任务全程禁止对 dsh/ 做任何写操作，此步只作为前置条件说明。

### 2. （可选，推荐）对齐 peerDependencies 版本范围

文件：`package.json:52-62`。将 7 个 `@deepseek-ai/*` peer 的 `"^0.1.2-alpha.1"` 统一替换为 `"^0.1.2-alpha.2"`（`@deepseek-ai/cordis` 的 `^4.0.1` 与 `react` 的 `^18.2.0` 不动）。这是版本卫生，不改也不影响运行——本机是 `link:` 安装，实际类型/实现来自 dsh 源码树。

### 3. 重建插件（本机 profile 是 `link:` 引用，重建 `lib/` 即可见，无需 `dsh plugin update`）


以下验证需在 **dsh web 进程重启 + 浏览器硬刷新（Ctrl+Shift+R）之后**进行（link: 引用下 `lib/` 重建即生效，但 client bundle 与 host 插件都要新进程 + 新模块表加载）：

2. **加载无报错**：重启 `dsh web` 后控制台无 `Failed to load plugins` / `missed the module table` / `Cannot find package '@deepseek-ai/dsh-client-*'`（若出现，指向的是 alpha.2 源码树未 install/build，回查步骤 1，而非插件问题）。
