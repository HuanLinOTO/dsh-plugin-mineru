# DSH 插件 API 迁移参考：0.1.2-rc.1 → 0.1.5-alpha.2

> 本文件是全局参考，逐条列出让第三方插件受影响的 API 变化。目标版本即本机 checkout
> `D:/Projects/deepseek-harness/dsh`（工作树 == `dsh-v0.1.5-alpha.2`，`lib/` 已构建）。
> 环境注意：本机无 `C:/Users/Administrator`，凡 tsconfig paths / devDependencies link: 指向
> `C:/Users/Administrator/.dsh/source/current/` 的一律改为 `D:/Projects/deepseek-harness/dsh/`。

## 0. 通用（所有插件）

- vendor 包（@deepseek-ai/cordis 4.0.2 / cosmokit / schemastery / cordis-plugin-*）：**两版完全一致**，无需改 API。
- `peerDependencies` 里的 `@deepseek-ai/*` 版本范围按仓库既有风格抬到 `0.1.5-alpha.2` 基线
  （`^0.1.2-rc.1` → `^0.1.5-alpha.2`；`>=0.1.2-rc.1` → `>=0.1.5-alpha.2`；`^0.0.1` 等远古写法酌情对齐仓库惯例）。
- 打包契约不变：`dsh.bundle.patch`、`cordis.patch.yml` insert 行（id/name/config）、
  `window.__ModuleLoader__.load({ id, factory })`（无新增必填字段）、预构建 `lib/` 策略全部照旧。
- `@deepseek-ai/dsh-app-boot` 的 `DshBundleManifest` / `DshProfileManifest` / `DshManifestSection` /
  `ProfilePatchReload` 类型**移到了新包 `@deepseek-ai/dsh-package-manifest`**（types-only break）。
- 新平台模块：`@deepseek-ai/dsh-client-ui-dockkit` 进入 web 平台基线 externals（可直接 require）。
- 本机路径重定向（tsconfig paths、devDeps link:、pnpm-workspace overrides 里的绝对路径）**不要提交**。

## 1. 服务端 session / agent / tools / llm

### dsh-session（BREAKING）
- `SESSION_FORMAT_VERSION` 0→3；`SessionHeader.version` 收窄为字面量 3。
- 子路径导出 `./chunk-rows` 删除（`decodeStorageRecord`/`packChunkRuns`/`ChunkRow`/`StorageRecord` 全没了）。
- 事件：`tool/code-dispatch(-start)` → `tool/ptc-dispatch(-start)`；`assistant/chunk` 移除（改走 `assistant/attempt` / scoped 事件 `agent/assistant-stream`）；新增 `system/message`、`assistant/attempt`。
- `assistant/message` data 新增必填 `stream: AssistantStreamRecord[]`，且禁止携带 `sourceEventSeqs`（append 会 throw）。
- `SurfaceOp.replace` 字段 `start/end` → `startSeq/endSeq`。
- `EpochHeader.system` 移除（system prompt 改为 surface 上的 `system/message` 事件派生）；append 带 `header.system` 的 `request/header` 会 throw。
- `Session.fromRestore` 新增第 5 个必填参数 `eventState: SessionSeedEventState`（`'detached' | 'shared-frozen'`）；`SessionStore.prepare` 的 `seedSource: 'persistence'` 被 `eventState` 取代。
- `Session.append` 校验收紧（事件数据 + surface 元数据校验），rc.1 能过的数据现在可能 throw。
- `request/header` reason `'change'` → `'series'`。

### dsh-agent（BREAKING）
- `Inbox` 从 class 变 interface：`hasPending()`、`claim()`、`InboxNotifications` 移除；保留 `nextTurn/nextStep/clear/append/prepend/replace/remove/splice`。
- `ctx.agent` 访问器**移除**。AgentSetup 回调改为 `(agentCtx, agent)` 双参；子 agent 用第二参拿。
- `ctx.agentLoop.create(...)` 变 async，必须 `await`。
- 新事件 `agent/assistant-stream`（`{ agent, frame }`）；`CreateAgentOptions/ResumeAgentOptions` 新增可选 `parentAgent`。

### dsh-tools（仅事件词汇）
- `defineTool` 及 `schema.ts` **字节级不变**，注册工具的插件不受影响。
- 观察侧：`tool/code-dispatch*` 事件名改 `tool/ptc-dispatch*`；子调用 id `<parent>:code:<n>` → `<parent>:ptc:<n>`；deferred 源标签 `tools-code-mode` → `tools-ptc`。

### dsh-llm（ADDITIONS）
- `LlmRuntime` 签名全不变（新增 `fileRequestText(ref)`）。
- 新增 `FileBlock`（`ContentBlockMap` 新增 `'file'` 变体 → **穷举 switch 需补 case**）、`SystemMessage`/`createSystemMessage`、assistant-stream 模块、`LlmAttemptId`。
- `PreparedLlmCall.systemPromptUpdate?: 'in-history'`；loop 请求的 system prompt 改走 leading system 消息。

## 2. api / typert / system-prompt / commands / attachment

### dsh-api-session-controller（BREAKING）
- Config 移除 `coldBlankProbeMaxBytes`（只剩 `{ nativeOpen }`）。
- wire 类型：`SessionWireHeader.seedLength` → `isSeeded: boolean`；`SessionChunkRun`/`ChunkRowEvent` 删除（历史记录=纯事件）；`SessionWireSurfaceOp.replace` 用 `startSeq/endSeq`；`PromptContentPart` 新增 file 变体（receiptId）。
- client 面：`PendingSubmission.images` → `attachments`；`ISession.beginSubmission` 的 `images` → `attachments`；`SessionCommandsRemote.execute(agentId, line, attachments: CommandSubmitAttachment[], signal)`；inject 新增 `'connection'`、`'fileUpload'`。
- `ApiSessionList` 构造签名 `(ctx, coldBlankProbeMaxBytes)` → `(ctx)`。

### dsh-api-remotes（BREAKING）
- Agent-scoped waterfall 转发不再用 `ctx.typert.contexts.identifyHost(...)` 识别，直接读 `request.agent`，缺失/不匹配直接 TypeError。**插件 emit `approval/request`、`user-questions/request` 等必须带 `request.agent`。**
- 转发表新增 `goal/activation-changed`（emit）。client 组合多挂 `commandFeedback`/`fileUploads`/`workspaceFiles` remotes（additive）。

### dsh-api-gateway（BREAKING）
- `TypertRemoteEventContext` 新增**必填** `agentId: string`。
- `RemoteJournalFrame/Change/Stream` 增加第 4 个泛型 `Notification = never`（默认值保兼容；穷举消费者需处理 `notification` 帧）。

### dsh-typert-protocol / dsh-typert-registry（BREAKING）
- 导出 `TypertContextAdapter`、`TypertHostContextIdentity` 删除。
- `TypertContextRegistry.identifyHost(ctx)` 方法**删除**；host adapter 不再需要 `identity(ctx)`（对象字面量多余属性会被查）。

### dsh-system-prompt（BREAKING，配置级）
- Config `persona` → `personaPrefix`（新增 `personaSuffix`）；旧 key 会被 schema 拒绝。
- `PERSONA_SECTION` 移除 → `PERSONA_PREFIX_SECTION = 'deployment:persona-prefix'` + `PERSONA_SUFFIX_SECTION = 'deployment:persona-suffix'`。
- `SECTION_ORDERS` 变化：`HARNESS_SOURCE` −900→10000、`WEB_SURFACE` −800→10100。按绝对序号贡献 section 的要对位。

### dsh-commands 契约（跨包 ripple）
- 命令注册 `input.images: true` → `input.attachments: true`。
- `commands.execute(agent, line, attachments: CommandSubmitAttachment[], signal)`（原 `EncodedImageAttachment[]`）。
- 新增 `ctx.commands.registerFileReceiptResolver(agent, receiptId)`。

### dsh-attachment
- 模块级导出 `admitPromptContent` **移除** → 改用服务方法 `ctx.attachments.admitPromptContent()`；新增 `admitEncodedFile()`、`isAttachmentError`、`FileAttachmentRef`。

### dsh-message-feedback（BREAKING）
- 旧导出全删（`messageFeedbackDomainSpec`、`messageFeedbackItemSchema`、`MessageFeedbackRow` 等）；存储从 sidecar domain 改为会话事件 `feedback/message-put` / `feedback/message-delete`（走 `ctx.sessionPersistence` handle）。
- `MessageFeedbackPutRequest` 新增 `category?`（来自新包 `@deepseek-ai/dsh-command-feedback/types`）。

### 其他
- `dsh-settings`：**不变**。
- `dsh-brand`：**不变**。`dsh-user-approval` / `dsh-user-questions`：**不变**。
- `dsh-scope`：additive（新 scoped subject `agent/assistant-stream`）。
- `dsh-plan-mode`：`/plan` 命令 `input.images` → `input.attachments`；错误文案 image→attachment。
- `dsh-workspace`：`WorkspaceRegistry.create/resolveByPath` 要求 fully-qualified 路径（相对路径 throw）。
- `dsh-session-query`：Config `persistedInspectConcurrency` → `persistedReadConcurrency`；新增 `preparedSessionCacheSize`。
- `dsh-session-persistence`：**重写**。抽象面改为 `create/open(id,'read'|'write')/flush/stat/list` + `SessionHandle`（AsyncDisposable）；`locate/readRaw/append/load/inspect/borrowSession/readFrom/list*`、coordinator/preparations/write-behind 全删；新增错误类（`SessionAlreadyExistsError`/`SessionReadOnlyError`/`SessionHandleClosedError` 等）。
- `dsh-session-query` 之上，session 存储格式 v3：packed chunkrow 历史没了，assistant 流进 `assistant/message`/`assistant/attempt` 的 `stream` 字段。
- `dsh-subagent`：`seedDescriptorTurn` 移除；`HostPromptQueue` → `HostPromptDeliverer`（方法带 `SubagentDelivery` 前参）；`SubagentPromptRequest` 新增必填 `delivery: 'queue' | 'steer'`；`queueSubagentPrompt` → `deliverSubagentPrompt`（symbol 也换了）。
- `dsh-fs`：抽象类新增抽象方法 `readByteRange(target, {offset,length}, signal?)` —— **自定义 FileSystem 子类必须实现**。
- `dsh-llm-pi-ai`：`route.piProvider` 变 optional（原来必填）；`RouteCatalog.modelErrors` 必填；`resolveRouteModels`/`assertServiceable`/`resolveProfiles`/`toPiReplayState` 均有 additive 参数；pi-ai 依赖 ^0.84.2→^0.85.1。
- `dsh-attachment` 之外新概念：`FileUploadReceiptId`（新包 `@deepseek-ai/dsh-client-file-upload`）。

## 3. client 基础设施

### dsh-client-connection（BREAKING-ish）
- `ConnectionFetchRoute` 新增必填 `requestBody: 'buffered' | 'streaming'`；method 放宽 +`'POST'`。旧 route 对象在 0.1.5 host 上 `requestBody === undefined` 会被当 streaming 处理。
- 实现 `ConnectionFetchHandler` 接口的必须补 `requestBodyMode({method,url})`；旧 `FetchHandler` 接口删除。
- `ConnectionConfig` → `ConnectionRecoveryConfig`（默认 `generationReadyTimeoutMs` 3000→15000）；页面全局 `__DSH_CONNECTION_RECOVERY__`。
- host 侧 inject 从 `['webServer','credentials']` → `['credentials']`（webServer 变可选）。

### dsh-client-store / dsh-client-locale
- store：**src 不变**；`zustand`/`immer` 转 devDeps（预打包）。直接引 lib 的消费者要自带。
- locale：**API 不变**（仅版本）。

### dsh-host-webserver
- **src 不变**。HTTP API 通道推荐改走 `ctx.connection.fetch.register({ path, methods, requestBody, fetch })`。

### ui-chat（BREAKING）
