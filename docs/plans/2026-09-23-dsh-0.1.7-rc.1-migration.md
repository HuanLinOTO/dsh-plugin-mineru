## 行动

1. **RC1-01 peer 提升**：`package.json` 7 个 `@deepseek-ai/dsh-*` peer `^0.1.5-rc.1` → `^0.1.7-rc.1`。
2. **RC1-15 核验**：`dsh.bundle.patch = "./cordis.patch.yml"`（字符串形式在 rc.1 仍合法）；无被删字段 `dsh.profile.patchReload`/`dsh.configTrees`/`dsh.sessionFormatMigration`/`dsh.moduleFallback`。
3. **schemastery 依赖切换**（见「额外发现」）：`dependencies` 的 `schemastery@^3.18.0` → `@deepseek-ai/schemastery@^3.18.4`；`src/index.ts:19` import 同步。运行时仍内联进 `lib/`，与旧行为一致。

## 额外发现（无对应卡，primary source 支撑）

rc.1 起 DSH 的 vendor schemastery 升到 `@deepseek-ai/schemastery@3.18.4`，新增 `SchemaMode` / `Volatile`、`Schema` 变 3 泛型；它与插件原用的普通 `schemastery@3.18.0`（同为 `declare global { namespace Schemastery }`）在同一 tsc program 内**全局命名空间合并**，令 `z.object({...})` 回退到分叉版重载，`Schema<...>` 与显式标注 `z<Config>` 不再可赋值。`plugin-development-guide.md` 红线清单要求 vendor/schemastery 作为宿主提供的依赖使用，故统一改为 `@deepseek-ai/schemastery`。本插件 Config 无数组默认值，未触发报错，但同样存在该类型隐患，一并切换以保持一致。
